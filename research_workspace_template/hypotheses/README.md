# hypotheses/ — 가추·최소 가설

## 역할
큰 그림을 한 번의 실험으로 판정할 수 있는 최소 가설로 쪼개고, 검증 전 기각 기준과 판정을 남긴다.

## 입력 → 출력
- 입력: `bigpicture.md`, `wiki/gaps.md`의 공백·RQ, 실험에서 나온 새 관찰
- 출력: `H{nn}_<짧은이름>.md` (양식: `_template.md`)

## 작업 순서
1. 공백이나 관찰에서 가설 후보를 세우고, 대안 설명을 함께 적는다.
2. 한 번의 실험으로 판정할 수 없으면 더 쪼갠다. RQ 하나가 가설 여러 개가 될 수 있다.
3. 사전 기각 기준을 쓰고 사람의 확인을 받는다. 확인된 날짜를 `criteria_locked`에 적고 기준을 잠근다.
4. 불확실성이 크고 검증 비용이 작은 가설부터 `bigpicture.md`의 "다음에 검증할 가설"에 올린다.
5. `manuscript/draft.md` Results에 이 가설의 절을 `[대기]`로 만든다.
6. 판정이 나면 `CLAUDE.md`의 "판정이 나면 한 번에 갱신할 것"을 따른다.

## 지킬 것
- 상태는 `후보` / `검증중` / `채택` / `기각` / `보류` 다섯 가지만 쓴다.
- `criteria_locked`가 비어 있으면 검증을 시작하지 않는다.
- 잠근 기각 기준은 고치지 않는다. 바꿔야 하면 새 가설(`H{nn}`)로 만들고 원래 가설에 링크한다.
- 기각된 가설 파일은 지우지 않는다.
- 시뮬레이션 결과로는 채택도 기각도 확정하지 않는다. "실험 대상으로 올림" 또는 "보류(이유)"만 쓴다.
- 채택·기각 확정은 사람이 한다. 에이전트는 사전 기준 대비 판정을 제안한다.
