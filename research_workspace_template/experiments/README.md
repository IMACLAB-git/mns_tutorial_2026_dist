# experiments/ — 검증 기록

## 역할
가설을 판정하는 실험, 시뮬레이션, 기준선 재현을 한 형식으로 기록한다. 실험은 사람이 하고, 에이전트는 프로토콜 초안·분석·기록을 맡는다.

## 입력 → 출력
- 입력: 가설 페이지(사전 기각 기준), 사람이 넣은 원데이터
- 출력: `E{nn}_<짧은이름>/` (양식: `_template/`)
  - `protocol.md`: 종류(실험 / 시뮬레이션 / 기준선 재현), 연결 가설, 조건, 변수, 반복 수, 보정, 판정 기준
  - `data/`: 원데이터
  - `analysis/`: 분석 스크립트
  - `result.md`: 스크립트가 낸 수치, 오차, 사전 기준 대비 판정 제안

## 작업 순서
1. `_template/`을 복사해 `E{nn}_<짧은이름>/`을 만든다.
2. 가설 페이지의 사전 기각 기준을 그대로 옮겨 `protocol.md`를 쓴다. 가설의 `criteria_locked`가 비어 있으면 멈춘다.
3. 새 셋업이면 기준선 재현(`E00`)을 먼저 한다. 대상 논문의 대표 수치를 같은 조건에서 재현하고, 그 수치와 원문 위치를 `protocol.md`에 적는다.
4. 사람이 실험하고 `data/`에 원데이터를 넣는다.
5. `analysis/` 스크립트로 수치를 계산하고 `result.md`에 판정을 제안한다.
6. 사람이 확정하면 `CLAUDE.md`의 "판정이 나면 한 번에 갱신할 것"을 따른다.

## 지킬 것
- 원데이터는 고치지 않는다. 제외한 데이터는 이유를 적는다.
- 결과 수치는 분석 스크립트 출력에서만 가져온다. 손으로 옮기지 않는다.
- 근거 등급: `실험`과 `기준선 재현`은 [실험], `시뮬레이션`은 [시뮬]이다. [시뮬]은 가설을 거르는 데만 쓴다.
- 기준선을 재현하기 전에는 개선을 주장하지 않는다.
- 문헌 수치와는 측정 조건이 같을 때만 비교한다.
- 장비·재료를 보유했는지 확인하지 못했으면 `needs_review`로 적는다.
- 실패하거나 기각으로 끝난 실험 폴더도 지우지 않는다.
